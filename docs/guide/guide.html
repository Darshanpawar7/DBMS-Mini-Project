1. What is ScholarMesh?

A website where students upload their study notes, search them by meaning (not just exact words), and get matched into study groups with classmates who study the same topics.

The problem

  • Notes are scattered across Drive folders, WhatsApp groups and laptops.
  • Normal search only finds exact words. Searching "how do models decide which words matter" finds nothing, even though a note called "Transformers and Self-Attention" explains exactly that.
  • Finding study partners is random — you ask around in class groups.

What ScholarMesh does

Search by meaningAsk in your own words. The app understands what you mean and finds the right notes, even with no matching words.
Smart study groupsSuggests groups and classmates whose interests are closest to yours. Seat limits are enforced.
Safe sharingEach note is public, course-only or private. Nobody ever sees a note they are not allowed to.

Who uses it

RoleWhat they can do
StudentUpload notes, search, save (bookmark) notes, enroll in courses, create / join / leave study groups, see their dashboard.
Group adminA student who created or runs a group: edit the group, promote or remove members.
AdminPlatform manager: usage charts, manage users and roles, manage courses and tags, read the audit log.

Why it counts as a DBMS project (not just a CRUD app)

  • Two kinds of database in one: normal tables (SQL) for users, courses and groups, plus a vector store (pgvector) for the meaning of notes.
  • The database enforces the rules itself using triggers, constraints and transactions — e.g. a full group can never accept another member, even if two students click "Join" at the same moment.
  • Uses views, a materialized view, stored functions and procedures, indexes, full-text search, vector search and an audit log.

Why PostgreSQL + pgvector (Option 2) instead of a separate vector database? Because the meaning-search and the "who may see this note?" check run in the same SQL query, a private note can never leak into results. Foreign keys also keep the vectors in sync with the notes — delete a note and its vectors disappear in the same transaction.

3. How it works

The big picture

The journey of a note

  1. Upload — a PDF, TXT or Markdown file (or pasted text). The server pulls out the text.
  2. Save — in one transaction: the note is saved, and a database trigger splits the text into short passages (≤ 800 characters). If anything fails, nothing is saved.
  3. Understand — the AI model turns every passage into 384 numbers (an embedding). Passages with similar meaning get similar numbers.
  4. Find — the note can now be found by its words and by its meaning.

The three search modes

ModeHow it worksThink of it as…
KeywordMatches the actual words (full-text search, GIN index), ranks by relevance, highlights matches.Ctrl+F across all notes
SemanticTurns your question into 384 numbers and finds the passages whose numbers are closest (cosine similarity, HNSW index).A librarian who understands what you mean
Hybrid (default)Runs both and merges the two rankings (Reciprocal Rank Fusion), so exact words and meaning both count.The best of both

Who can see which note

Public → every logged-in user · Course-only → students enrolled in that course · Private → only the owner (and admins). One database function, fn_visible_doc_ids, makes this decision for every search, list, download and suggestion.

How study-group matching works

Each student gets an interest vector: the average meaning of the notes they uploaded or saved and the questions they searched. A group's interest is the average of its members'. Groups in your courses with a free seat are ranked by how close they are to you (70%) plus how many topic tags you share (30%). Classmates are ranked the same way.

Rules the database enforces by itself

  • A group can't go over its seat limit — the group row is locked while someone joins, so two people can't take the last seat.
  • Only students enrolled in a course can create or join its groups. The creator automatically becomes group admin.
  • If the last admin leaves, the longest-standing member becomes admin; an empty group is deleted.
  • Dropping a course removes you from its groups. Deleting a course turns its course-only notes private.
  • Passwords must be bcrypt hashes (plain text is rejected). E-mails, tags and semesters must be in the right format.
  • Every important change (roles, notes, courses, groups) is written to an audit log with who did it.

The database at a glance — 12 tables

5. Run it on your computer

Install these once (all free):
  • Docker Desktop — docker.com/products/docker-desktop (runs the database)
  • Node.js 20 or newer (LTS) — nodejs.org (runs the website)
  • Git — git-scm.com (downloads the code)
You also need internet the first time (downloads ~1 GB of packages/images and a 23 MB AI model).

The commands below work in PowerShell (Windows) and in the Terminal on Mac/Linux.

1

Get the code

git clone https://github.com/Darshanpawar7/DBMS-Mini-Project.git
cd DBMS-Mini-Project
2

Start the database (Docker)

Open Docker Desktop first and wait until it says it is running. Then:

cp .env.example .env           # database settings (example passwords are fine for local use)
docker compose up -d           # downloads and starts PostgreSQL + pgvector on port 5433
3

Set up the website

cd web
cp .env.example .env.local     # app settings (already match the database settings)
npm install                    # installs packages (a few minutes the first time)
4

Create the tables and load the demo data

npm run db:setup               # builds all tables, triggers, functions + demo data
npm run db:embed               # AI model reads every note (first run downloads the model)
5

Start the app

npm run dev

Open http://localhost:3000 and log in:

Next time you only need: open Docker Desktop → in the project folder run docker compose up -d → then cd web and npm run dev. Stop the app with Ctrl + C; stop the database with docker compose down (your data is kept).
Sharing the computer or a network? Change the passwords in .env, put the same app password into web/.env.local (inside DATABASE_URL), and set AUTH_SECRET to a random value: node -e "console.log(require('crypto').randomBytes(48).toString('base64url'))". Then run npm run db:setup again.

If something goes wrong

ProblemFix
docker says it cannot connectDocker Desktop is not running. Open it, wait a minute, try again.
"password authentication failed for user scholarmesh_app"The app password in web/.env.local doesn't match APP_DB_PASSWORD in .env. Make them equal, then npm run db:setup.
Port 3000 or 5433 already in useApp: npm run dev -- -p 3001. Database: change POSTGRES_PORT in .env and the port in DATABASE_URL, then docker compose up -d.
Semantic search finds nothing / notes show "Embedding…"Run npm run db:embed (needs internet the first time to download the model).
Want the original demo data backnpm run db:setup then npm run db:embed (inside web).
